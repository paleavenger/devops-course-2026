# Git vs SVN: ключевые различия

## 1. Почему ветвление в Git "дешёвое", а в SVN — "дорогое"?
Git хранит ветку как лёгкий указатель (40-байтный хэш) на коммит — создание ветки не копирует файлы. SVN исторически создавал ветку как полную копию каталога в репозитории (svn copy), что физически (хоть и через copy-on-write на сервере) тяжелее и медленнее, особенно на больших репозиториях, плюс слияние (merge) в SVN сложнее отслеживать, так как нет полноценного распределённого графа коммитов.

## 2. Можно ли в SVN сделать коммит без интернета?
Нет, нельзя. SVN — централизованная система: рабочая копия хранит только текущее состояние файлов, а вся история — на центральном сервере. svn commit сразу отправляет изменения на сервер, поэтому без сети коммит невозможен. В Git коммит делается локально (в локальный .git), а на сервер отправляется отдельно через push.

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?
Большие бинарные файлы (игровые ассеты, видео, CAD) — SVN лучше работает с ними за счёт частичного чекаута.
Нужен частичный/выборочный чекаут только части огромного репозитория (SVN поддерживает это нативно).
Строгий централизованный контроль доступа по папкам (enterprise-политики).
Команда привыкла к линейной модели и не нуждается в сложном ветвлении/слиянии.
Legacy-инфраструктура, где переход на Git дорог.
